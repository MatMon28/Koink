# Reminder notifications

> **Scope:** Settings > Notifications: the four reminders, their defaults and ids, how Android and the browser deliver them, permissions, what a tap opens.
>
> **Read when:** you touch `src/lib/reminders.ts`, `src/lib/notifications.ts`, `src/lib/useReminders.ts`, `src/sheets/NotificationSettings.tsx`, or the notification parts of `android/`.
>
> **Related:** [android.md](android.md), [pwa.md](pwa.md) (the worker's part), [features/settings.md](features/settings.md), [known-gaps.md](known-gaps.md)

Everything is opt-in (all off by default), scheduled on the device, and never leaves it: there is no push server. The choices live in `settings.notifications`, so they are part of the journal and of a backup.

| Reminder | You choose | When | A tap opens |
| --- | --- | --- | --- |
| **Daily reminder** | a time (21:00) | every day | Add expense |
| **Recurring items** | a time (09:00) | on the day of the month each recurring item is due; items due the same day share one notification | the Recurring checklist, on the current month |
| **Weekly review** | a weekday (Sunday) and a time (18:00) | once a week | Statistics |
| **New month** | a time (09:00) | on the 1st | Budgets |

The Recurring row cannot be switched on while there are no recurring items. It says how many reminders a month that makes (one per distinct due day).

## How it works

```
settings.notifications + recurring items + currency
        |  buildNotificationPlan()        src/lib/reminders.ts   (pure)
        v
  PlannedNotification[]   id, channel, title, body, hour, minute, day? / weekday?, target
        |  useReminders()                 src/lib/useReminders.ts (mounted once, in App.tsx)
        +--> Android: syncNativeNotifications()   repeating system alarms
        +--> browser: startWebReminders()         timers while the app is open
```

- **The plan** is a pure function, so the same list drives both platforms and can be tested without a device. Ids are stable (a reminder always replaces itself): recurring `2000 + day of month` (2001-2028), daily `3001`, weekly `3002`, new month `3003`, test `9001`. A recurring notification names its item and amount (`Rent is due today` / `€820.00. Tap to log it.`), says `is expected today` for income, and lists up to three names when several are due.
- **`useReminders`** turns the plan into text and re-syncs only when that text changes (a setting, a recurring item, the currency). It also listens for taps and hands the target to `openTarget()` in `App.tsx`.

### Android (`@capacitor/local-notifications`)

`syncNativeNotifications()` cancels everything pending and schedules the plan again, each alarm with `schedule.on = { hour, minute, second: 0 }` plus `day` (monthly) or `weekday` (weekly), and `allowWhileIdle`. They are repeating alarms in the system alarm manager: they arrive with the app closed and the plugin restores them after a reboot. Calls are queued, debounced by 400 ms and run in an idle moment (`whenIdle`), so stepping through a time field does not reschedule on every change.

- **Channels** (the user can tune each in Android's settings): `koink-daily`, `koink-recurring`, `koink-reviews`.
- **Icon:** `res/drawable-*dpi/ic_stat_koink.png`: the whole Koink logo (K, pig, coin) in white on a transparent background, which Android tints `#286540` (`capacitor.config.json` > `LocalNotifications`). Android only uses the alpha channel, so the K is cut away around the pig and the pig's lines are heavier than in the colour logo. It is found by name, so `res/raw/keep.xml` protects it. Generated by `npm run brand`; details in [brand.md](brand.md#notification-icon).
- **Permissions** (`AndroidManifest.xml`): `POST_NOTIFICATIONS` is asked at run time on Android 13+ the first time a reminder is switched on; `RECEIVE_BOOT_COMPLETED` restores alarms after a restart; `SCHEDULE_EXACT_ALARM` is declared, and without that special access the plugin uses inexact alarms (a few minutes late at most).
- The plugin module is imported on demand and only inside the app (`nativePlugin()`), so the website never downloads it.

### Browser and installed PWA

The same plan runs on timers, so a reminder arrives **only while Koink is open** (a tab in the background counts). Settings says so. Each timer waits for `nextOccurrence()` and is cut into pieces of at most six hours, so a sleeping laptop or a changed clock cannot strand it.

A notification is shown through the offline worker when there is one (`registration.showNotification`: Chrome on Android allows no other way), otherwise with `new Notification`. A tap is handled by the worker's `notificationclick` (it focuses the window and posts `{ type: 'koink:open', target }`), or opens `./?open=<target>` when no window is left; `takeLaunchAction()` reads that parameter.

## Settings sheet

`NotificationSettings.tsx` is the collapsible **Notifications** group. Switching a reminder on asks for the system permission (the tap is the gesture browsers need). It shows a banner when notifications are blocked or unavailable, an **Allow notifications** button while permission is pending, and **Send a test notification** (immediately in a browser, after two seconds on Android), which reports the outcome in a toast.

## Changing it

- **A new reminder:** a field in `NotificationSettings` (`types.ts`) with a default and validation in `reminders.ts`, a block in `buildNotificationPlan()` with a new id, a row in `NotificationSettings.tsx`, and, if it opens somewhere new, a value in `OpenTarget` handled by `openTarget()` in `App.tsx`.
- **Wording:** all notification text is in `buildNotificationPlan()`; channel names in `NOTIFICATION_CHANNELS`.
- Old journals and backups without `notifications` load with everything off (`normalizeNotificationSettings`).
- **Delete all data** keeps the settings, so reminders stay as chosen; recurring-item reminders disappear with the items.
