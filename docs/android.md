# Android app: how it works

> **Scope:** the Capacitor shell: configuration, the native project, what was changed in the template, the plugins and the JavaScript that talks to them.
>
> **Read when:** you change `capacitor.config.json`, anything in `android/`, a Capacitor plugin, or code behind `isNativeApp()`.
>
> **Related:** steps in [prepare-apps.md](prepare-apps.md); every native file in [file-map/android-native.md](file-map/android-native.md); [notifications.md](notifications.md); [gestures.md](gestures.md); [known-gaps.md](known-gaps.md)

**Status: generated and synced, never compiled or run** (that includes the three Java files). There was no Android SDK where this was written. Treat everything below as the design; the device checklist is in [prepare-apps.md](prepare-apps.md#first-run-on-a-device-check-these).

## Shape

The Android app is the same web build inside a WebView. The only Java of its own is small and about one thing, the launch colour: `MainActivity` (a `BridgeActivity`), `LaunchBackground` and the plugin `KoinkDevicePlugin` ([launch-intro.md](launch-intro.md)). The web files are served from the APK at `https://localhost/` (`androidScheme: https`), so `localStorage`, absolute asset paths and secure-context APIs behave as on the website. No network is needed or used.

## Hand edits on top of the Capacitor template

`npx cap add android` produced the project. These are the differences; reapply them if the folder is ever regenerated (`npm run android:prepare` checks for the pieces the web side counts on):

1. **Icons**: every `mipmap-*/ic_launcher*.png` (legacy, round, adaptive foreground, monochrome) and `drawable-*dpi/ic_stat_koink.png` (notification icon) is rendered by `npm run brand` ([brand.md](brand.md)). `mipmap-anydpi-v26/ic_launcher*.xml` gained a `<monochrome>` layer (Android 13+ themed icons); `values/ic_launcher_background.xml` is the tile colour `#F9F3E6`.
2. **Launch screen** ([launch-intro.md](launch-intro.md#one-background-colour-from-the-tap-on-the-icon-to-the-app)):
   - `values/colors.xml` (new): `launch_background` = `#EFE9DD`, the fallback.
   - `values/styles.xml`: `AppTheme.NoActionBarLaunch` sets `windowSplashScreenBackground`, a transparent icon (`drawable/splash_blank.xml`, new) and `postSplashScreenTheme`. The template's `android:background=@drawable/splash` line and its eleven `splash.png` images are gone: the launch screen is a colour only.
   - `values/splash_themes.xml` (generated by `npm run android:splash`): one `Splash_<hex>` style per app background.
   - Java, in `app/src/main/java/com/koink/app/`: `MainActivity` registers the plugin and sets the window and WebView background before the page loads; `LaunchBackground` stores the colour and switches the launch-screen style (Android 13+); `KoinkDevicePlugin` is the bridge (`setLaunchBackground`).
3. **`AndroidManifest.xml`**: three `uses-permission` lines for reminders, with a comment: `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, `SCHEDULE_EXACT_ALARM`. The notifications plugin declares the same in its own manifest; they are repeated so everything the app asks for is visible in one place.
4. **`res/raw/keep.xml`** (new): keeps what is only found by name (`Splash_*` styles, `ic_stat_koink`) if resource shrinking is ever switched on.

Nothing else (Gradle files, the activity and provider entries of the manifest) was touched. Besides the three above, the only permission is `INTERNET`, from the template.

The Java follows the reference app's launch-colour code closely. It uses `Activity.getSplashScreen().setSplashScreenTheme` (API 33, guarded) and nothing outside the Android SDK and Capacitor.

## Generated, not committed

`cap sync` (run by `npm run android:prepare`) writes these; `android/.gitignore` excludes them:

- `android/app/src/main/assets/public/`: the web build
- `android/app/src/main/assets/capacitor.config.json`, `capacitor.plugins.json`
- `android/capacitor-cordova-android-plugins/`

`android/capacitor.settings.gradle` and `android/app/capacitor.build.gradle` are also rewritten by every sync (they list the plugins): never edit them.

## JavaScript side

| Need | Code | Native piece |
| --- | --- | --- |
| "Am I the Android app?" | `isNativeApp()` in `src/lib/platform.ts` | `Capacitor.isNativePlatform()` |
| Back button / back swipe | `initBackHandling()` in `src/lib/back.ts`: dismiss the top layer, else `App.minimizeApp()` | `@capacitor/app` |
| Save a backup | `saveTextFile()` in `platform.ts`: write the JSON to the app cache, open the share sheet with it | `@capacitor/filesystem`, `@capacitor/share`; the template's `FileProvider` (`res/xml/file_paths.xml`) already exposes the cache directory |
| Restore a backup | plain `<input type="file">` in `SettingsSheet.tsx` | handled by Capacitor's WebView |
| Reminders | `syncNativeNotifications()`, `listenForNotificationTaps()`, `sendTestNotification()` in `src/lib/notifications.ts`, driven by `useReminders()` | `@capacitor/local-notifications`: repeating alarms, three channels, the `ic_stat_koink` icon (the whole logo as a white-on-transparent PNG) |
| Launch colour | `syncLaunchBackground(color)` in `platform.ts`, called by the theme effect in `store.tsx` with the computed `--bg` | the app's own plugin `KoinkDevice` (`KoinkDevicePlugin.java`), registered in `MainActivity`, not through `capacitor.plugins.json` |
| Status / navigation bar icon colour | `syncSystemBars(theme)` in `platform.ts`, called by the theme effect in `store.tsx` | `SystemBars` (part of `@capacitor/core`) |

The plugin modules for files and sharing are loaded with `import()` only when a backup is saved; `@capacitor/app` and `@capacitor/local-notifications` only inside the native app.

Web-only features are switched off natively: no offline worker (not built in `--mode android`, not registered), no install card, no project-download card, no history sentinel for Back. The launch animation, Ultra minimal and all gestures are the same web code and run unchanged.

## Adding a plugin

`npm i @capacitor/<name>`, use it behind `isNativeApp()` in `platform.ts`, run `npm run android:prepare` (the sync adds it to the Gradle files), add it to the check list in `scripts/prepare-android.mjs`, and document it here and in [file-map/android-native.md](file-map/android-native.md).
