# Known gaps

> **Scope:** what is unverified, missing, or deliberately left out, so nobody assumes otherwise.
>
> **Read when:** you plan work, or something behaves differently from what another document says.
>
> **Related:** [verification.md](verification.md), [android.md](android.md), [pwa.md](pwa.md)

## Unverified

1. **Android build and run.** `android/` was generated by Capacitor and synced, but never compiled: no JDK / Android SDK in the authoring environment. The three hand edits to resources ([android.md](android.md#hand-edits-on-top-of-the-capacitor-template)) are standard, yet untested. First thing to do on a machine with Android Studio: `npm run android:prepare`, then Run.
2. **Backup sharing on Android** (`saveTextFile()` in `src/lib/platform.ts`): written against the plugin types, never executed. If the share sheet does not accept the cache file, check the `FileProvider` paths in `android/app/src/main/res/xml/file_paths.xml`.
3. **Safe areas on Android.** The layout relies on `env(safe-area-inset-*)` with `SystemBars.insetsHandling: "native"`. Check the header and the dock on an old WebView (< 140) and a current one.
4. **Real devices.** All touch testing was emulated in desktop Chromium. iOS Safari was not tried at all.

3a. **Reminders on Android** (`syncNativeNotifications()` in `src/lib/notifications.ts`, the manifest permissions, `ic_stat_koink.png`): written against the plugin's types, never run. Check the permission prompt, a reminder with the app closed, after a reboot, and the tap.
3b. **Real browser notifications.** Tests stubbed the permission and the display call ([verification.md](verification.md)). Try *Send a test notification* in a real browser.

3c. **The launch-colour Java** (`MainActivity`, `LaunchBackground`, `KoinkDevicePlugin`) was written without a compiler at hand. It follows the reference app's code line for line where it can, but treat a compile error there as possible, and check on a phone that changing the theme changes the launch screen on the next cold start (Android 13+).
3d. **Themed (monochrome) launcher icon and notification icon** were only looked at as images, never on a device.

## Decisions and limits

5. **Capacitor is pinned to 8.5.3**, not the newest 8.x: `@capacitor/cli` 8.6 depends on `xcode@^4`, which could not be installed here, so core, android and cli were pinned to the same earlier version. When that resolves, raise all three together and run `npx cap sync android`.
6. **The launch screen follows the theme only on Android 13+.** `setSplashScreenTheme` does not exist before that, so on Android 12 and older the system launch screen stays the default oat whatever the theme (window, WebView and the animation still use the saved colour). The first launch after installing also uses the default. A background with no matching `Splash_<hex>` style (run `npm run android:splash` after changing a `--bg`) leaves the launch screen on its previous colour.
7. **No home-screen widgets and no guided tour.** The reference app has both (widgets as native Java, a tour built on embedded copies of the app). They are not part of this project.
7a. **Browser reminders only fire while Koink is open.** There is no push server; background delivery needs the Android app.
7b. **A recurring reminder does not know the item is already logged.** Repeating system alarms have fixed text, so it fires on the due day either way.
7c. **On touch devices up to three pages are mounted** (the current one and its hidden neighbours), so data changes re-render them too. Cheap at this size; revisit if pages grow heavy.
8. **No update prompt.** A new web version is used from the launch after the worker updated ([pwa.md](pwa.md)).
9. **No iOS app.** Only `android/` exists. iPhone users install the PWA.
10. **`android:prepare` overwrites `dist/`** with the Android build (no offline worker). Run `npm run build` again before deploying the website.
11. **Mouse users cannot swipe pages.** The page swipe is touch and pen only; the header pill does the same job.
12. **One currency, no conversion.** The journal's currency is locked once it holds amounts, because a change would relabel (not convert) them ([features/currencies.md](features/currencies.md)). There is no migration flow yet (pick a new currency, preview every converted amount, confirm); until then the way out is backup, Delete all data, pick the currency.
13. **Categories are fixed in code** (`src/lib/categories.ts`); there is no screen to add one.
14. **English only.** The reference app also ships Italian; no translation layer was carried over.
15. **Storage is `localStorage`.** It is per browser and per origin: the website, the installed PWA on another browser, and the Android app each have their own journal. Move data with Save backup / Restore backup. Clearing site data deletes the journal.

## Leftovers from the project template

16. `framer-motion` and `react-router-dom` are installed but not imported.
17. `vite.config.ts` contains template lines (an optional `.vite-source-tags.js` import, `process.env` defines) that the app does not need; they are harmless and were left alone. Two ESLint findings come from them ([verification.md](verification.md)).
18. `android/app/src/test` and `androidTest` hold Capacitor's example tests under the package `com.getcapacitor.myapp`.
19. `index.html` ends with a large `<script data-element-picker>` block added by the preview tool the project was built in. It is not part of the app.
20. **Standalone animation files** (`public/brand/koink-intro-*.svg`) clip at their 1024 canvas, so parts that fly in from outside (the pig of *pop-toss*, *peek*) enter at the edge. In the app the art overflows its box and nothing is clipped.
21. **The name Koins** survives in two compatibility shims only (storage keys and cache names of builds from before the rename): [brand.md](brand.md#rename-koins---koink).

## Added with widgets, gift cards and the pig icon

- The Android widgets (`KoinkWidgetProvider.java`, layouts, manifest receivers) were written without an Android SDK and `javac`: not compiled, not run on a launcher. Check on a device: the three widgets appear in the picker, placing one shows the buttons after the app was opened once, a tap opens the right sheet (also with the app closed), resizing keeps the tiles even.
- Widget icons are rendered by the WebView, so the home-screen widgets update only when the app has been opened after a change in Settings > Widgets (the app pushes the change within a second of the edit).
- The blurred-hero-card fix is based on a screenshot; the cause could not be reproduced without the device (see [features/month.md](features/month.md)).
- A gift card has no transfer or top-up: to change its value, edit it. A card's balance never goes below zero.
- Widgets exist in the browser only as the strip on the Month page (browsers have no home-screen widgets).

## Added with accounts, categories and currencies

- No transfers between accounts; entries without an account count nowhere in Accounts.
- Exchange rates are approximate until **Update exchange rates** is used (online, [Frankfurter](https://frankfurter.dev)); Frankfurter lists about 30 currencies, the others keep the built-in approximate rate; a foreign entry keeps the rate it was saved with.
- Recurring items with a frequency above one month get no reminder notification (the alarm repeats monthly); only monthly items do.
- The Android widget changes (no text on buttons) were written without an Android SDK, like the rest of `android/`: not compiled.
- Custom category and account names use the phone keyboard (text cannot come from a number pad).
- Not run on a device: the sheet-drag and header-scroll smoothness was checked in headless Chromium only (no frame-time measurement on a phone).

## Language and the new widgets (latest round)

- The Italian texts were written without a native review. Reminder notifications, the sample journal and the Android widget picker names stay English.
- The new widget look (round buttons, circle / pill / card trays, theme colours) was written without an Android SDK, like the rest of `android/`: the RemoteViews layouts, `setViewPadding` / `setColorFilter` calls and the tray drawables are untested on a device. The in-app version was built and type-checked only; no browser was available to look at it.

## Added with weekly recurring items, the expense chart and the filter panel

- A weekly recurring occurrence is matched to its entry by **date**. If you edit the date of a logged occurrence, it stays on the checklist as its own line and the original due date is offered again.
- Weekly recurring items have no reminder notification.
- The expense chart at day resolution over a long period is a wide, sideways-scrolling chart (at most 800 bars); the custom statistics period is limited to 60 months.
- The Transactions filter panel (categories, accounts, dates, amounts) is not remembered between visits, only whether it is open.
- The *Day cards* layout was removed; the new screens were built and type-checked but **not tested on a phone**.
- The expense chart's comparison, line and full view (and the month sections of the Transactions page) were type-checked, linted and the date maths (`comparisonPeriod`) was run, but they were **not looked at in a browser or on a phone**. When comparing periods the slots are lined up by position, so a week-resolution comparison of two periods that start on different weekdays pairs weeks that are not exactly the same days.

## Added with data safety and Excel export

- **The not-saved banner and the restore preview were exercised with a stubbed failing `setItem` and by unit-style runs of the helpers, not on a real full or blocked browser store.** Safari private mode, quota on Android WebView and `beforeunload` behaviour on mobile browsers (which often ignore the prompt) are untested.
- A write is considered successful when `localStorage.setItem` does not throw; there is no read-back check, so a browser that silently discards writes would not be noticed.
- The restore dialog's *Save a copy* uses the normal backup download; on the Android app the share sheet may be dismissed, which counts as not saved.
- The currency lock looks at the journal only. Restoring a backup in another currency is allowed (the preview warns about it).
- **The Excel file is a snapshot, not a backup**, and has only been opened by reading its XML and sheet list, not in Excel, LibreOffice or Numbers. Dates are real Excel dates (UTC midnight); money uses `#,##0.00` with the currency code in the header rather than a currency format. It covers every entry; budgets are for the month open in the app. See [features/excel-export.md](features/excel-export.md).
- The Excel library (`write-excel-file`, about 80 kB) is a separate chunk loaded on demand, but the offline worker precaches it with the rest of the build.
