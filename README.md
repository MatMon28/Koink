# Koink

A local-first journal for income, expenses, budgets and savings, built with React 19, TypeScript, Vite and Tailwind CSS v4. One codebase ships three ways: a website, an installable offline **PWA**, and an **Android app** (Capacitor shell in `android/`). There is no account and no backend; the journal lives in the browser's `localStorage`. The look (warm oat palette, pastel cards, pill navigation, bottom dock, bottom sheets, six style presets) follows the [Kakcal](https://github.com/MatMon28/Kakcalculator) design system, and so do its habits: a launch animation, pages that swipe on one rail, opt-in reminder notifications, an Ultra minimal mode, sheets that never get in the way.

> **Renamed:** the app was called *Koins*. It is **Koink** everywhere now (name, logo, Android id `com.koink.app`, storage keys, file names). A journal saved in a browser under the old name is moved over on first launch: [docs/brand.md](docs/brand.md#rename-koins---koink).

## Quick start

```sh
npm ci
npm run dev                 # browser preview with hot reload
npm run build               # dist/: website + PWA (manifest, icons, offline worker)
npm run package             # public/downloads/koink-project.zip: the whole project, downloadable from Settings
npm run brand               # every icon, wordmark and animation file from src/brand/art.js (needs: npm i --no-save sharp)
npm run android:prepare     # Android build of the web app, synced into android/
npm run android:open        # open android/ in Android Studio
```

Node.js 22+ is required; Android also needs JDK 21 and Android SDK 36. Full steps for both apps: **[docs/prepare-apps.md](docs/prepare-apps.md)**.

### Rules that save tokens

1. State and every action come from one hook: `useApp()` in `src/lib/store.tsx`. Start there for any behaviour change.
2. Colours are CSS variables (`--bg`, `--surface`, `--text`, ...) plus the Tailwind tokens `intake` (money in), `activity` (money out), `weight` (savings), `nutrient` (yellow note cards). The names are inherited from the reference app on purpose: see [design-system.md](docs/design-system.md) before renaming anything.
3. Every sheet is a `<Modal>`; every sheet is opened with `openSheet({ type: ... })`. The list of types is the `Sheet` union in `src/lib/types.ts`.
4. After adding, renaming or deleting a file, update its row in `docs/file-map/` and, if it is a feature, the matching `docs/features/*.md` (rule and table in [docs/README.md](docs/README.md#keeping-the-docs-current)).
5. A new screen, sheet, field, button, icon or label follows section 4 of [guide to UI UX fixes.md](guide%20to%20UI%20UX%20fixes.md#4-rules-for-future-features) (reuse the shared pieces, tokens instead of hex colours, one icon per meaning, text through `t()`). Fixing an old inconsistency: find its ID in section 2 of that file and tick it in section 6.

## Latest round: swipes that never wait, a pill that follows the pages

Reworks the page swipe (`PageSwiper.tsx`) and the header pill (`Tabs.tsx`, `lib/pillTab.ts`). Checked with `tsc`, `vite build` **and in headless Chromium with real touch events** on a lab page that runs these files unchanged (about 90 scripted swipe sequences, a 60-sequence random run against a model, and the same suite against the old code, which failed 18 of its checks). **Not run on a real device or in the full app** ([docs/known-gaps.md](docs/known-gaps.md)).

- **No swipe is ever ignored, and there is no dead time at the end.** A finger that lands while a committed swipe is still travelling **lands that page at once and carries on from where the page visibly is** (the rail's offset is re-expressed from the new page, so nothing jumps). Two or more quick swipes in the same direction therefore end two or more pages from the start; a swipe the other way **turns the rail round** and goes back to the page it came from. Before, the new touch landed the first page and then started from rest, and a finger on the part of the rail that was still sliding in (the neighbouring page was `inert`, the 24 px gap and the margins belonged to nothing) ended the animation instead of catching it. [docs/gestures.md](docs/gestures.md#catching-the-rail-a-new-gesture-during-an-animation)
- **The release is decided by the finger itself** (which way, how far, how fast, measured from the page that is current), not by where the rail happens to be: this is what makes chaining and turning round predictable. Distances and speeds are unchanged. [docs/gestures.md](docs/gestures.md#sensitivity)
- **The pill follows the pages all the time.** One coloured indicator slides behind the buttons and is placed by a single number, the rail position (`0` = first page, `1.5` = half way between the second and the third), which `PageSwiper` publishes every frame while a finger drags, while a committed swipe travels and while a cancelled one springs back. Position, width, the label of each tab (it opens and closes with the weight of the tab) and the **colour** (one pastel layer per page, cross-faded) change gradually with the pages, never at a given point. Tapping the pill glides it (260 ms). The bottom dock still reacts when a swipe is committed (`usePillTab`). [docs/gestures.md](docs/gestures.md#the-pill-follows-the-rail)
- **Touch-action.** The column around the rail now has `touch-action: pan-y` too, otherwise the browser cancelled a sideways touch that started in the gap between two pages.
- Changed code: `src/components/PageSwiper.tsx`, `src/components/Tabs.tsx`, `src/lib/pillTab.ts`, the `Page pill` block at the end of `src/index.css`. No new dependency, no stored data. Docs updated: this file, `docs/{gestures,motion,known-gaps,changes-patch}.md`, `docs/file-map/{components,lib}.md`. `changes.patch`: [docs/changes-patch.md](docs/changes-patch.md).
